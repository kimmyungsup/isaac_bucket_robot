Isaac Bucket Robot 개발 요약
최종 갱신일: 2026-07-29

1. 본 코드의 목적
이 프로젝트는 NVIDIA Isaac Sim에서 이동식 버킷/사다리 로봇과 양팔 로봇을 시뮬레이션하고,
키보드로 주행·사다리 관절·양팔 말단 자세·도장 작업을 제어하기 위한 코드이다.
단일 로봇 실행과 여러 로봇을 한 스테이지에서 제어하는 멀티 로봇 실행을 지원한다.

2. 주요 실행 코드
- combined_mobile_keyboard_control.py
  공통 진입점이다. 무인자 실행과 -m 옵션은 멀티 로봇 제어를 실행하며,
  --robot 인자를 지정하면 해당 단일 로봇을 wheel 버전으로 실행한다.
- multi_robot_control.py
  humanoid, v4_onlyarm, only_mobile 로봇을 한 스테이지에서 선택하여 제어한다.
- target_area_selector.py
  PaintWall_A/PaintWall_B 위의 직사각형 도장 목표 영역을 지정하고 도장 완성도를 계산한다.
- painting_simulation.py
  로봇 노즐의 raycast 결과를 이용해 직사각형 도장 및 원형 스프레이 패치를 생성한다.
- control_status_ui.py
  현재 모드, 제어 상태, 도장 상태와 도움말을 표시한다.

3. 현재 구현된 주요 기능
- 키보드 기반 로봇 선택, 주행, 사다리 관절 및 양팔 제어
- 말단 장치 궤적 시각화
- 노즐 raycast 기반 직사각형 도장과 원형 스프레이 시각화
- PaintWall_A와 PaintWall_B를 대상으로 한 도장 목표 영역 지정
- 단일 로봇 및 멀티 로봇 모드 지원
- 상태창을 통한 제어 모드, 관절 상태, 도장 상태 표시

4. 도장 목표 영역 지정 방법
- 숫자 5 키로 TARGET AREA 모드에 진입한다.
- 마우스로 PaintWall_A 또는 PaintWall_B를 가리키면 유효한 충돌 위치에 초록점이 표시된다.
- 첫 번째 대각선 모서리에서 F 키를 누른다.
- 두 번째 대각선 모서리에서 F 키를 누르면 목표 직사각형이 확정된다.
- 좌클릭 선택은 사용하지 않는다.
- PaintWall_B의 실제 prim 이름은 대소문자가 다른 paintWall_B일 수 있으므로,
  target_area_selector.py에서 이름을 대소문자 구분 없이 자동 탐색한다.

5. 목표 영역 시각화
목표 영역이 확정되면 아래 prim이 생성된다.
- /World/PaintTargetArea/Confirmed/Outline: 초록색 직사각형 테두리
- /World/PaintTargetArea/Confirmed/Corners: 네 개의 초록색 모서리 점

목표 영역 내부의 반투명 Fill Mesh는 도장 결과를 가리기 때문에 생성하지 않는다.
모드를 변경해도 확정된 테두리와 모서리는 유지된다.
새 목표 영역을 확정할 때 기존 Confirmed 영역이 새 영역으로 교체된다.

6. 도장 완성도 계산
- 목표 직사각형을 100 x 100 셀로 나누어 도장된 셀의 누적 비율을 계산한다.
- 직사각형 도장과 원형 스프레이 패치가 모두 계산에 포함된다.
- 목표 영역 밖의 패치는 제외하며, 중복 도장 영역은 한 번만 계산한다.
- 결과는 0.0%~100.0% 범위로 상태창 Paint 항목에 표시한다.
- 목표 영역이 없으면 "No target area"로 표시한다.
- 새 목표 영역을 지정하면 coverage=0.0%로 초기화한다.
- C 키로 도장 패치를 지울 때도 현재 목표 영역의 완성도를 0.0%로 초기화한다.

7. 최근 수정 사항
- PaintWall_B가 선택되지 않던 prim 경로 및 대소문자 문제 수정
- 초록 hover 점을 벽면에서 약간 띄우고 크기를 키워 depth fighting 완화
- 목표점 선택 입력을 좌클릭에서 F 키로 변경
- 목표 영역의 반투명 Fill 제거
- 도장 패치 기반 목표 영역 완성도 계산 및 상태창 표시 추가
- 멀티 로봇 초기화 시 paint=None인 only_mobile 로봇에 콜백을 등록하여 발생하던
  AttributeError를 수정하고, 도장 기능이 있는 로봇에만 콜백을 연결

8. 주요 키
- 5: TARGET AREA 모드 진입/복귀
- F: TARGET AREA 모드에서 현재 초록점 위치를 모서리로 선택
- Z: 활성 팔의 직사각형 도장 켜기/끄기
- X 누르기: 원형 스프레이
- C: 생성된 도장/스프레이 패치 삭제 및 완성도 초기화
- ESC: 종료

F 키는 ARM 모드에서는 base/tool 제어 프레임 전환, MOBILE 모드에서는 일부 관절 제어에도
사용되지만 TARGET AREA 모드의 분기와 분리되어 있어 목표점 선택과 충돌하지 않는다.

9. 검증 상태
- target_area_selector.py
- painting_simulation.py
- combined_mobile_keyboard_control.py
- multi_robot_control.py
- control_status_ui.py

위 파일은 Python py_compile 구문 검사를 통과했다.
멀티 로봇 모드는 실제 시작 검사를 수행했으며 기존 paint=None AttributeError 없이
combined_mobile_humanoid 선택 및 DRIVE 모드 진입까지 확인했다.

10. 다음 작업 시 확인할 사항
- Isaac Sim 뷰포트에서 두 벽 모두 F 키 선택과 테두리 표시가 정상인지 확인
- 실제 도장 궤적으로 coverage 값이 증가하고 100%를 초과하지 않는지 확인
- 벽의 반대 면이나 평행한 다른 면의 도장이 목표 영역에 포함되지 않는지 확인
- 필요하면 COVERAGE_GRID_SIZE(현재 100)를 조정하여 정확도와 성능 간 균형 조절
- 상태창 표시 문구나 소수점 자릿수는 coverage_status 속성에서 변경


11. 현재 실행 정책과 사용 USD
- uv run python combined_mobile_keyboard_control.py
  인자가 없으므로 기본 멀티 로봇 모드로 실행한다.
- uv run python combined_mobile_keyboard_control.py -m
  명시적으로 멀티 로봇 모드로 실행한다.
- uv run python combined_mobile_keyboard_control.py --robot humanoid_base
  mobile_bucket_humanoid.usd의 wheel 로봇을 실행한다.
- uv run python combined_mobile_keyboard_control.py --robot v4_onlyarm
  mobile_bucket_onlyarm.usd의 wheel 로봇을 실행한다.
- -w/--wheels 인자는 제거되었으며 단일 로봇은 항상 wheel 버전이다.

12. FOB 6D 팔 제어 연동 (2026-07-30)
- 기본 직렬 포트: /dev/ttyUSB1, 115200 baud
- FOB/fob_control_bridge.py가 기존 fob_6d_pose_visualizer.py의 PoseSource를
  재사용하여 제어 루프를 막지 않고 최신 6D 자세를 공급한다.
- humanoid와 onlyarm의 ARM 모드에서 P 키로 FOB 모드에 진입/해제한다.
- FOB 모드 진입 시 현재 센서 자세와 선택 팔의 end-effector 자세를 기준으로 잡는다.
- 위치와 Azimuth/Elevation/Roll 변화량을 선택 팔 목표 위치/방향에 적용한다.
- FOB 제어 좌표에서 Y 위치축 부호를 반전한다: position_sign=(+1,-1,+1).
- 같은 Y축 반사 좌표계를 회전에도 적용하여 Roll/Pitch/Yaw 부호를
  (-1,+1,-1)로 사용한다.
- R 키는 FOB 모드에서 현재 센서/팔 자세를 기준으로 다시 잡는다.
- FOB 모드에서도 X(누르는 동안 분사), Z(사각 도장 토글), C(도장 지우기)가 유지된다.
- 상태창 FOB 행에는 connected, connecting, connection failed 또는 stale data가 표시된다.
- 센서 미연결, serial open 실패, 데이터 중단은 시뮬레이션을 종료하지 않고 처리한다.
- 단일/멀티 로봇 제어 모두 같은 FOB 브리지를 사용한다.

주의:
- fob_6d_pose_visualizer.py와 Isaac Sim 제어 코드는 /dev/ttyUSB1을 동시에 열 수 없다.
  시각화 프로그램으로 연결을 확인한 후 종료하고 제어 코드를 실행한다.
- Arduino Nano 스위치는 /dev/ttyUSB0, 9600 baud를 기본으로 사용한다.
- 실제 수신 형식인 단일 ASCII 'A'를 active-high ON 이벤트로 인식한다.
- FOB 시각화와 Isaac Sim 상태창에서 Arduino 연결 및 ON/OFF 상태를 확인한다.
- FOB 모드에서는 키보드 X 또는 Arduino ON 중 하나만 활성화되어도 분사한다.
- 버튼 ON 이벤트 1회는 기본 0.35초 분사 펄스로 변환한 뒤 자동 OFF한다.
- 버튼을 누른 동안 A가 반복 수신되면 펄스 만료가 갱신되어 연속 분사한다.
- 이벤트형 장치이므로 무신호 대기 자체는 연결 오류로 판단하지 않는다.
- arduino_switch_reader.py를 직접 실행하면 raw hex/ASCII/파싱 결과를 확인할 수 있다.
- 좌표/회전 스케일 기본값은 FOB/fob_control_bridge.py에서 조정한다.

Python 제어 코드에서 사용하는 스테이지 USD는 다음 세 개뿐이다.
- mobile_bucket_humanoid.usd
- mobile_bucket_onlyarm.usd
- mobile_bucket_multi-robot.usd

기존 non-wheel/legacy USD는 더 이상 제어 코드에서 참조하지 않는다.
상태창의 Slots 행에는 1~5번 점유 상태가 표시되며, 로봇이 없는 슬롯은 EMPTY로 표시한다.
현재 멀티 스테이지는 1=humanoid, 2=v4 onlyarm, 3=only_mobile,
4=EMPTY, 5=EMPTY이다.
